# Phase 12 — النسخ الاحتياطي والاستعادة (Backup + Restore)

## الملفات الجديدة / المعدّلة

| الملف | النوع | الوصف |
|---|---|---|
| `HR.DAL/BackupDAL.cs` | جديد | الوصول لجدول BackupLogs: Insert / MarkRestored / LastBackupTime / Search |
| `HR.BLL/BackupBLL.cs` | جديد | منطق النسخ والاستعادة + النسخ التلقائي + الصلاحيات + Audit |
| `HR.UI/UI/FrmBackupRestore.cs` | جديد | شاشة النسخ الاحتياطي والاستعادة (اختيار مجلد، شبكة ملفات، شبكة سجل العمليات) |
| `HR.UI/UI/FrmMain.cs` | تعديل | ربط miBackup بالشاشة + مؤقت النسخ التلقائي كل 60 ثانية |

ملاحظة: ملفات `.cs` تُضمن تلقائيًا عبر `<Compile Include="**\*.cs" />` في كل csproj — لا تعديل على ملفات المشروع.

## الميزات

1. **نسخ احتياطي يدوي**: زر «نسخ احتياطي الآن» — نسخ ملف MDB المفتوح حاليًا إلى المجلد المحدد (الافتراضي: مجلد البيانات\Backups) باسم `ModernTime_yyyyMMdd_HHmmss.mdb`.
2. **نسخ احتياطي تلقائي**: يوميًا مرة واحدة عند الوقت `Backup.AutoTime` (الافتراضي 23:30) إذا كان `Backup.AutoEnabled = YES` — يُفحص كل 60 ثانية من FrmMain عبر `RunAutoBackupIfDue()`، والفحص «مرة يوميًا» عبر `LastBackupTime(TypeAuto)`.
3. **استعادة**: اختيار ملف من شبكة الملفات (.mdb/.bak الأحدث أولًا) → تحذير مزدوج (فقدان بيانات + إغلاق الأجهزة الأخرى) → نسخة أمان PreRestore أولًا → الكتابة على الملف الحالي → تسجيل عملية Restore.
4. **سجل النسخ**: جدول BackupLogs يُعرض في الشاشة (النوع، الملف، الحجم، الوقت، الحالة، مسار الاستعادة).

## الصلاحيات والأمان

- النسخ اليدوي والاستعادة وقراءة السجل تتطلب `Backup.Execute` — النسخ التلقائي لا يتطلب صلاحية (يعمل من الخلفية بمعزل عن المستخدم النشط).
- الاستعادة ممنوعة من ملف قاعدة البيانات نفسه (target ≠ current).
- نسخة أمان PreRestore تُنشأ قبل أي استعادة، فلا تُفقد البيانات القديمة ولو فشلت الاستعادة.
- كل عملية (نسخ/استعادة/فشل) تُسجل في AuditLog وفق القاعدة 22.

## قرارات القاعدة 36 (تعارضات / غير محدد)

| القرار | التبرير |
|---|---|
| النسخ التلقائي «مرة واحدة يوميًا» عبر BackupLogs وليس ملف مؤشر خارجي | الحالة Single Source of Truth داخل قاعدة البيانات؛ لو نُسخت قاعدة البيانات يدويًا لا يُفقد منطق التوقيت |
| الوضع الآمن عند فشل النسخ التلقائي: تسجيل في السجل + عدم إظهار رسالة تعطيل النظام | القاعدة 26 — الفشل يجب ألا يوقف تشغيل المستخدمين الآخرين؛ السجل يكشف الفشل |
| عند الاستعادة تُكتب صفوف Restore داخل قاعدة البيانات المُستعادة نفسها، بينما صف PreRestore يبقى محفوظًا فقط داخل ملف الأمان | قيد فيزيائي: الكتابة تجري بعد الكتابة فوق الملف؛ الملف الأصلّي يحتفظ بالسجل الكامل |
| الاحتفاظ الدوراني (Retention/Rotation) لم يُنفذ عمدًا | ليس ضمن متطلبات القاعدة 23؛ يُضاف لاحقًا كإعداد `Backup.KeepCount` عند الطلب |
| شاشة الإعدادات FrmSettings غير منفذة بعد (miSettings ما زال ShowPhaseNotice) | الإعدادات `Backup.AutoEnabled`/`Backup.AutoTime` قابلة للتعديل حاليًا مباشرة من جدول SystemSettings؛ تُغطى بشاشة الإعدادات في المرحلة 13 |

## خطوات الاختبار

1. افتح النظام → النسخ الاحتياطي → اختر مجلدًا → «نسخ احتياطي الآن» → تأكد من ظهور الملف في الشبكة وفي المجلد، وصف Completed في سجل العمليات.
2. أدخل بدون صلاحية `Backup.Execute` (مستخدم User) → الزران معطّلان.
3. حدد نسخة قديمة → «استعادة المحدد» → أكّد التحذير المزدوج → تحقق: نسخة أمان PreRestore تُنشأ قبل الكتابة، والنظام يستمر بعد إعادة التشغيل.
4. حاول اختيار ملف قاعدة البيانات المفتوح نفسه → تُرفض العملية برسالة واضحة.
5. اجعل `Backup.AutoEnabled='YES'` + `Backup.AutoTime` = وقت بعد دقائق → اترك النظام مفتوحًا → تُنشأ نسخة Auto مرة واحدة فقط.
