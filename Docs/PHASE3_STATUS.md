# Phase 3 — شاشات الهيكل التنظيمي والموظفين (مكتملة)

## منجز
- **مشروع `HR.UI`** (WinExe, x86, .NET 4.0 Client Profile, VS2012) مع `App.config`
  ومراجع المشاريع الأربعة، وإدراج تلقائي `**\*.cs` في `HR.UI.csproj`.
- **`Program.cs`**: تهيئة `DbInitializer.EnsureInitialized()` + `UserBLL.InitializeFirstAdmin()`
  + `SettingsBLL.Refresh()` عند الإقلاع، ومعالج أخطاء مركزي لخيط الواجهة وللخيوط الأخرى
  (رسالة عربية للمستخدم + تفاصيل في السجلات — BR-23، دون إظهار Stack Trace للمستخدم).
- **`Theme.cs`**: RTL عربي، خط Cairo مع fallback إلى Segoe UI، ألوان هادئة،
  شبكة موحدة `StyleGrid`، ورؤوس موحدة، ورسائل موحدة (خطأ/معلومة/تأكيد).
- **`FrmLogin.cs`**: تسجيل الدخول مع قفل الحساب بعد المحاولات الفاشلة، و`FrmChangePassword.cs`.
- **`FrmMain.cs`**: قائمة التنقل (الموظفون، الهيكل التنظيمي)، تسجيل الخروج، تغيير كلمة المرور.
- **`FrmEmployees.cs`**: بحث + فلترة قسم/حالة + ترقيم تحميل تدريجي (100 صف)،
  إضافة/تعديل/إيقاف/تفعيل/أرشفة وفق الصلاحيات (`Employees.Add/Edit/Archive`)،
  ترجمة الحالة للعربية وتلوين الحالات.
- **`FrmEmployeeEdit.cs`** (بعد المراجعة الحرجة §32/§33):
  - نمط موحّد لكل حقول اللاكيا: `Dictionary<int,string>` لكل كيان، وتُربط الأزواج
    (Id, Name) مباشرة عبر `BindingSource` مع `DisplayMember="Value"` و`ValueMember="Key"` —
    القيمة المحفوظة هي **Id الحقيقي** دائمًا: لا `SelectedIndex+1`، ولا مطابقة أسماء، ولا reflection.
  - قاعدة قرار (§36): مطابقة النص المقترحة سابقًا تفشل عندما يتشارك كيانان نفس الاسم
    المعروض (فرعان بنفس الاسم في شركتين)، فاختير تمرير زوج `(Id, Name)` نفسه عبر الربط —
    أضمن من مطابقة النص ولا يخالف أي ضمان مطروح.
  - عنصر حارس "(بدون)" بالمفتاح 0 للحقول الاختيارية (فرع/قطاع/وظيفة فعلية/مؤهل)،
    والحقول الإلزامية (شركة/قسم/مسمى/حالة) تبدأ غير محددة وتُلقي
    `BusinessException` عربية عند الإهمال.
  - تعبئة تتابعية صحيحة: الفروع تتبع الشركة، والقطاعات والوظائف الفعلية تتبع القسم،
    مع قواميس أب `Dictionary<int,int>` منفصلة (لا فرض تطابق `Items` مع مصدر).
  - إزالة كل الدوال الفارغة/الوهمية (`SelectedId<T>` القديمة، `IdOf`، `FilteredItem`،
    `OptionalLookupId`، `FindName` ذات `matcher`، `GetIdValue` بالـ reflection).
  - حقول نوع التعيين تُعرض بالعربية وتُخزَّن بالقيم المتعاقد عليها
    (Permanent/Contract/PartTime/Intern)، والأسماء الظاهرة تحمل لاحقة «(معطل)» للسجلات
    غير النشطة للحفاظ على وضوح المراجع القديمة.
- **`FrmLookupManager.cs`** (جديد): إدارة الجداول الثمانية
  (الشركات/الفروع/الأقسام/القطاعات/المسميات/الوظائف الفعلية/المؤهلات/الحالات):
  - إضافة/تعديل/تعطيل-تفعيل/حذف آمن، مع فلتر «تضمين المعطلة» وأعمدة الكود/الاسم/الأصل/الحالة.
  - كل الكتابة عبر `OrganizationBLL` فقط (حارس `Org.Manage` + Audit Log داخل الـ BLL)،
    والحذف يرفضه الـ BLL تلقائيًا للسجلات المستخدمة.
  - حوار الإضافة/التعديل يربط «الأصل» بنفس نمط `(Id,Name)` مع حارس «(بدون)».
- **تمديدات داعمة**: `LookupDAL.GetLookupRows` (قراءة عامة لأي جدول ضمن Whitelist)،
  `LookupRow.IsActive`، وغلاف `OrganizationBLL.Rows` لمنع أي وصول UI→DAL مباشر.

## الفحص البنيوي الآلي (قبل الكوميت)
- توازن `{}` / `()` / `[]` لكل ملفات HR.UI + `OrganizationBLL.cs`: **ناجح**.
- فحص منع خصائص C#6+ (`?.`، `$""`، `nameof`، expression-bodied، pattern matching،
  `out var`) — ولا يوجد أي منها — **ناجح** (الهدف C# 5.0 فقط).
- فحص عدم وجود TODO/Placeholder/أجزاء ناقصة أو دوال ترجع null/0 — **ناجح**.
- تدقيق مرجعي: جميع الرموز المستدعاة (BLL/DAL/Entities/Helpers) موجودة فعلًا؛
  لا يوجد أي SQL داخل Forms؛ كل كتابة تمر عبر الـ BLL.

## ما لم يُقرر بعد
- اسم المستودع `owner/repo` للدفع (بانتظار القرار).
