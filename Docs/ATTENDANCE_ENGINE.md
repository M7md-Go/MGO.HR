# محرك الحضور والانصراف — الوثيقة المرجعية

> الحالة: Phase 2 (الأمر 4e4c03e8). توثق البنية الحالية + إصلاحات
> A-01 (P0) و E-01 التي نُفذت. البنود غير المنفذة مسجلة صراحة.

## 1. البنية

```
AttendanceBLL.Recalculate (HR.BLL)          ← التركيب: تحميل + تشغيل + كتابة
 ├─ ScheduleBLL.LoadMonth لكل شهر بالفترة   ← الخلايا المعتمدة (موظف → يوم → وردية)
 ├─ AttendanceDAL.LoadMappedLogs            ← البصمات (+حافّة يومين لعبور منتصف الليل)
 ├─ AttendanceDAL.LoadApprovedLeaves/Missions/LoadHolidays/LoadManualKeys
 ├─ AttendanceEngine.Calculate (HR.Services) ← محرك حساب نقي: لا DB إطلاقًا
 └─ AttendanceDAL.WriteEngineResults         ← معاملة واحدة لكل النتائج
```

- **المحرك نقي**: `AttendanceEngine` لا يلمس قاعدة البيانات — كل المدخلات في
  `EngineCalculationInput` وكل المخرجات في `EngineCalculationOutput`
  (قابلية اختبار بالعزل — قاعدة معمارية من الأمر).
- **القواعد** تُقرأ من AppSettings في كل تشغيل (`LoadRules`): سماح التأخير/
  الانصراف المبكر، نافذة البصمة المكررة، عتبة/نسبة الإضافي، ساعات العمل
  المتواصل القصوى، أيام الراحة الأسبوعية.

## 2. تعريف يوم العمل: EmployeeId + FullDate (إصلاح A-01 — P0)

**الخلل السابق**: دمج خلايا عدة أشهر داخل `Dictionary<موظف, Dictionary<رقم-اليوم,
وردية>>` جعل الشهر الأحدث يكسو أرقام الأيام نفسها — كل شهر سابق في نافذة
إعادة الاحتساب (حتى 93 يومًا) كان يُحسب بورديات الشهر الأخير.

**الإصلاح**: المفتاح الداخلي = `DateTime.Ticks` (التاريخ الكامل):
- `EngineCalculationInput.ScheduleCells` → `Dictionary<int, Dictionary<long, int>>`.
- الدمج في `AttendanceBLL.Recalculate` بمفتاح `cellDate.Ticks`.
- الحل في `AttendanceEngine` عبر `cells.TryGetValue(date.Ticks, ...)`.

ملاحظة حدودية: `MonthData.Cells` (شهر واحد) يبقى `رقم-اليوم` بحكم أنه يمثل
شهرًا واحدًا فقط — الدمج متعدد الأشهر هو الوحيد الذي يستخدم Ticks.

## 3. حماية التعديلات اليدوية

- الأيام التي تملك سجلًا بـ `IsManuallyChg = True` تُحمَّل كمفاتيح
  `"EmployeeId|dateTicks"` (`AttendanceDAL.LoadManualKeys`) ويتخطاها المحرك
  تمامًا (`SkipKeys`) — لا يُعاد حسابها ولا يُكتب فوقها.
- **E-01 (نُفِّذ Phase 2)**: `WriteEngineResults` لا يحذف استثناءات المحرك
  لتلك الأيام بعد الآن (كانت تُحذف لأنها ضمن processedKeys) — استثناءات
  الأيام المحمية تبقى كما هي.
- **بيان ما حُفظ**: `RecalcSummary.PreservedManualDays` تحمل قائمة مقروءة
  «كود-الموظف @ تاريخ» لكل يوم محمي، وتظهر للمشغّل في رسالة نتيجة التشغيل
  (FrmAttendanceCalc) وتُدوَّن في AuditLogs داخل سجل `Attendance.Recalculate`
  (مقيمة حتى 15 عنصرًا ثم عدّاد — لتفادي تضخم سجل التدقيق في النوافذ الكبيرة).

## 4. Idempotency — إعادة الاحتساب للفترة نفسها

| النتيجة | الآلية |
|---------|--------|
| صفوف Attendance | upsert بمفتاح (EmployeeId, AttDate) المضمون بقيود UQ_Att — لا تكرار |
| الاستثناءات | حذف `CreatedBy IS NULL` فقط لكل يوم مُعالج + إعادة الإدراج — التعديلات اليدوية (`CreatedBy` مشتغل) تنجو |
| الإضافي التلقائي | كتابة مشروطة `Source='Auto' AND Status='Pending'` — الإضافي المعتمد/اليدوي لا يُمس |
| الأيام اليدوية | متخطاة كليًا (SkipKeys) + استثناءاتها محمية (E-01) |

## 5. حالات البصمات المدعومة حاليًا (بدليل المحرك)
